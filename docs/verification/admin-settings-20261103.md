# راستی‌آزمایی ذخیره تنظیمات و ارتباط داشبورد — ۲۰۲۶/۱۱/۰۳

شاخه: `feat/codespaces-live-stack-20261103`

## شواهد و مرز تشخیص

لاگ ارسال‌شدهٔ Codespaces نشان می‌دهد Build قبلی، Healthcheckها و
Auth Smoke موفق بوده‌اند. سه آزمون Playwright در مرحلهٔ راه‌اندازی
Chromium، به‌دلیل فقدان کتابخانه‌های سیستم شکست خورده‌اند؛ هنوز
خود صفحه در آن آزمون‌ها بررسی نشده است. لاگ شامل خطای runtime
مشخص از `/settings` یا `/overview` نیست. بنابراین علت مشکل جاری
نمای کلی را نمی‌توان از این لاگ به قطعی PostgreSQL نسبت داد.

## اصلاحات این مرحله

### ذخیره محتوای فارسی

مسیر جدید BFF تا ۲۰٬۰۰۰ نویسهٔ FAQ و ۴٬۰۹۶ نویسهٔ خوش‌آمدگویی را
می‌پذیرفت، ولی سقف کل Body فقط ۳۰٬۰۰۰ بایت بود. متن فارسی معتبر
می‌توانست بدون رسیدن به FastAPI با 422 رد شود. سقف اکنون مطابق
سقف JSON داخلی FastAPI، ۲۵۶ KiB است؛ محدودیت تک‌تک فیلدها،
اعتبارسنجی HTTPS، نشست و CSRF تغییر نکرده‌اند.

درخواست حجیمِ chunked متوقف و با 413 رد می‌شود. MIME مشابه
`application/jsonp` دیگر JSON محسوب نمی‌شود. UTF-8 معیوب رد می‌شود.
اگر PATCH موفق باشد ولی خواندن مجدد قطع شود، پیام «ذخیره تأیید نشد»
برمی‌گردد؛ این حالت با «قطع ارتباط پیش از ثبت» یکی نیست.

### تشخیص خطای داشبورد

Bridge شکست شبکه، timeout، خطای HTTP و پاسخ JSON معیوب را با
`requestId`، روش درخواست، مسیر بدون Query و کد وضعیت ثبت می‌کند.
رمز، Cookie، کلید HMAC، متن خطای Provider و اطلاعات Body در این
لاگ ثبت نمی‌شوند. احراز هویت و امضای دقیق بایت‌ها حذف نشده‌اند.
درخواست‌های تغییردهنده به‌طور خودکار تکرار نمی‌شوند.

نشست ابطال‌شده در درخواست داده به `/login?expired=1` هدایت می‌شود؛
403 ناشی از نبود مجوز همچنان مستقل است و تبدیل به ورود مجدد نمی‌شود.

### آماده‌سازی مرورگر Codespaces

از ریشهٔ مخزن اجرا کنید:

```bash
bash scripts/setup_browser.sh
```

این دستور نسخهٔ پروژهٔ Playwright را نصب، سپس
`playwright install --with-deps chromium` را اجرا می‌کند؛ در پایان
واقعاً Chromium را روی یک سند محلی باز و بسته می‌کند. نصب کتابخانه‌های
Linux ممکن است sudo بخواهد. این فرمان وارد حساب نمی‌شود، تنظیمات
فروشگاه را عوض نمی‌کند و هیچ Bot API را فراخوانی نمی‌کند.

## تست‌های اجراشده در محیط بررسی

- Node.js: **۳۵ تست موفق**؛ ۲۰ تست مسیر تنظیمات، ۸ تست Bridge و
  ۷ تست موجود CAPTCHA.
- قبل از اصلاح، ۴ تست تنظیمات و ۵ تست Bridge شکست خوردند؛ پس از
  اصلاح همان سناریوها موفق شدند.
- Python: **۳ تست موفق** برای ترتیب فرمان‌های آماده‌سازی مرورگر
  و توقف صحیح هنگام خطای نصب. npm/npx/node در این سه تست شبیه‌سازی
  می‌شوند؛ این نتیجه به معنای نصب مرورگر روی Codespace شما نیست.
- `bash -n scripts/setup_browser.sh`: موفق.

تست‌های مسیر و Bridge، کد واقعی TypeScript و Web Request/Response
را اجرا می‌کنند؛ فقط مرز Next.js/session و ارتباط خارجی FastAPI
شبیه‌سازی شده‌اند. این‌ها جایگزین Build کامل، PostgreSQL یا مرورگر
واقعی برنامه نیستند. تست CAPTCHA نیز به Provider واقعی وصل نمی‌شود.

## پذیرش واقعی روی Codespace

```bash
cd /workspaces/AiogramShopBot
git pull --ff-only origin feat/codespaces-live-stack-20261103
bash scripts/setup_codespace.sh start
bash scripts/setup_codespace.sh dashboard-probe
```

نیازی به reset، حذف Volume یا تولید مجدد Token نیست.
`dashboard-probe` اتصال SQL و چهار API امضاشده را به‌صورت Read-only
بررسی می‌کند. سپس `/settings` را در مرورگر تازه‌سازی کنید؛ یک تغییر
را ذخیره و پس از Refresh ماندگاری آن را بررسی کنید.

برای دیدن خطاهای تفکیک‌شده در صورت ادامهٔ مشکل:

```bash
docker compose --env-file .codespaces/live.env -f compose.codespaces.yml logs --tail=100 app dashboard
```

برای اجرای مستقل تست‌های واحد (پس از نصب وابستگی‌های dashboard-next):

```bash
cd dashboard-next
npm test
```

پذیرش کامل `next-dev-loop` هنوز نیازمند `next dev` با Turbopack،
`/_next/mcp` و `agent-browser` است. آن چرخه در این محیط اجرا نشده است؛
تست‌های واحد بالا را نباید به‌عنوان PASS آن ثبت کرد.
