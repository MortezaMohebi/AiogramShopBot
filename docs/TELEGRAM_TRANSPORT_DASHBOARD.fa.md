# مدیریت مسیر ارسال تلگرام

مسیر ارسال هر بات در Registry و بخش Relay Worker Pool همان بات تنظیم می‌شود. فهرست Relayها، اولویت مسیر و نسخهٔ کلید مستقل‌اند؛ یک Worker مشترک مجوز استفاده از کلید بات دیگر را ایجاد نمی‌کند.

1. Origin عمومی Worker را در `TELEGRAM_WORKER_ALLOWED_ORIGINS` مجاز کنید.
2. Worker را در پنل ثبت کنید و آن را به بات تأییدشده متصل کنید.
3. کلید مستقل بات را مرحله‌بندی کنید و UUID، هش توکن، نسخه و محدودیت‌های آن را در Secret سمت Worker با نام `RELAY_CLIENTS_JSON` قرار دهید.
4. تأیید مسیر را اجرا کنید. فقط تطبیق `getMe` با شناسهٔ تأییدشدهٔ همان بات و ثابت‌ماندن نسخهٔ تنظیمات اجازهٔ فعال‌سازی می‌دهد.

کلید و توکن در پاسخ‌های API پنل نمایش داده نمی‌شوند. خطای شبکه، نتیجهٔ نامعلوم یا تغییر تنظیمات نباید با ارسال دوبارهٔ پیام جبران شود. درخواست‌های خواندنی ممکن است از مسیر بعدی استفاده کنند؛ درخواست‌های تغییردهنده پس از خطای مبهم تکرار نمی‌شوند.

کنترل Webhook و Polling از مسیر خروجی جداست. Receiver برای فعال‌سازی به Credential تأییدشده و Lease انحصاری همان سرویس نیاز دارد؛ فعال‌شدن Relay Receiver را خودکار فعال نمی‌کند.

جزئیات Secret، هدرها، سهمیه‌ها و بررسی محلی در [راهنمای Worker](CLOUDFLARE_WORKER.fa.md) آمده است.
